# Simulation Standard v0.1

MarketTestBench simulations connect prepared data windows with strategy decision files. A data
session stores normalized market data and immediately creates stable data-specific `window_id`
values. A later benchmark run may sample from those data windows, but it must preserve the original
window identity. The strategy can run anywhere, but its uploaded output must follow this standard so
every simulation can be validated, stored, and evaluated with the same assumptions.

## Simulation Record

Each simulation has:

- `id`: generated by MarketTestBench.
- `name`: user-facing simulation name.
- `session_id`: prepared data session used by the strategy.
- `window_set_id`: the selected session or future benchmark run that exposes the usable
  `window_id` values.
- `strategy_name`: strategy or model name.
- `strategy_version`: optional strategy version, commit, or run tag.
- `status`: `valid`, `invalid`, or future evaluation states.
- `created_at`: catalog timestamp.

## Capital Base

MarketTestBench standard initial cash = 10000 USDT.

Strategy engines must calculate every position decision against this fixed capital base. The
strategy owns sizing, stop tracking, order tracking, and partial close logic. MarketTestBench does
not infer position size from percentages.

## Decision File Format

Decision files are sparse CSV event streams. Each row means "from this timestamp onward, set this
symbol's target net base-asset quantity to this value for this window." Do not write one row per
market bar unless the target quantity actually changes on every bar.

```csv
window_id,timestamp,symbol,target_quantity
window_0001,2024-01-01T00:00:00Z,BTCUSDT,0.0
window_0001,2024-01-01T01:00:00Z,BTCUSDT,0.125
window_0002,2024-03-12T08:00:00Z,ETHUSDT,1.4
```

Required columns:

- `window_id`: sampled benchmark window identifier.
- `timestamp`: ISO-8601 timestamp.
- `symbol`: symbol from the selected session.
- `target_quantity`: desired net base-asset quantity. Positive values are long, negative values
  are short, and `0.0` is flat.

Additional columns are allowed and preserved in the uploaded CSV files, but v0.1 validation ignores
them.

Rows are decision events, not a full market-data export:

- Only write rows where `target_quantity` changes.
- Unchanged timestamps are intentionally omitted.
- The evaluator carries the last known target quantity forward.
- Before the first decision event for a window/symbol, target quantity is `0.0`.
- A strategy with no signals may output a CSV with only the header row.

Decision timestamps do not have to equal candle open or close timestamps. Strategies that use
`aggTrades` may emit intrabar timestamps. The evaluator must align those events onto the execution
timeline according to `timestamp_alignment_policy`.

## Strategy Agent Input

A strategy agent should receive these paths:

- Session manifest path: the `manifest.json` file inside the selected session directory.
- Market data path: the selected session's `data/klines` directory.
- Simulation standard path: this document.

The agent must read `manifest.json`, iterate over `windows`, and use each window's:

- `window_id`
- `symbol`
- `interval`
- `start_time`
- `end_time`
- `session_path`

The agent must load market data from `session_path` when present. If it only receives the data
directory, it can locate files by matching `symbol`, `interval`, and `year_month`.

## Strategy Agent Output

The preferred output is one CSV file containing all decisions for all windows.

Required header:

```csv
window_id,timestamp,symbol,target_quantity
```

Rules:

- Use the exact `window_id` from the session manifest.
- Use the exact `symbol` from the session manifest.
- Use timestamps from the selected window's time range.
- Write only target-quantity change events; do not copy every input candle into the output.
- Calculate sizing inside the strategy using the fixed 10000 USDT initial cash standard.
- Emit `target_quantity` as the desired net base-asset quantity after the event.
- To close a position, emit the remaining desired quantity, commonly `0.0`.
- For partial closes or stop exits, the strategy must track its own open quantities and emit the
  resulting net target quantity.
- If the strategy has no signal for a window, omit that window's rows; it will be evaluated as flat.
- Save the final output as a `.csv` file, commonly `decisions.csv`.

## Window Mapping

The benchmark owns the data ranges. Users do not choose them in the strategy output CSV.

The intended flow is:

1. MarketTestBench downloads a data session.
2. Every accepted kline file immediately receives a stable, data-specific `window_id`.
3. The session manifest lists those windows with symbol, interval, start time, end time, row count,
   source file, and hash-derived identity.
4. A future benchmark run may select or split those windows, but any derived window must remain
   traceable to the source `window_id`.
5. The user strategy reads the manifest and writes target quantities for those `window_id` values.
6. The simulation upload validates the decisions against the manifest.

Two upload layouts are supported by the standard:

- Single CSV: one file containing all windows, distinguished by `window_id`.
- Multiple CSV files: one file per window, where the file name or rows identify `window_id`.

The preferred layout is a single CSV with `window_id`, because it is easier to upload, validate, and
version. Multiple CSV files remain useful for strategies that naturally emit one output file per
window.

Until benchmark window validation is fully enforced in code, the current MVP accepts session-level
decision CSVs without `window_id`. That is a temporary compatibility mode; new generated templates
should include `window_id`.

## Validation Rules

A simulation is valid only when all uploaded decision files pass validation:

- At least one CSV decision file must be uploaded.
- Every file must contain `timestamp`, `symbol`, and `target_quantity`.
- Header-only CSV files are valid and mean no target changes.
- Final benchmark-run validation will also require `window_id`.
- `timestamp` must be parseable as ISO-8601.
- `symbol` must exist in the selected session's kline files.
- `window_id` must exist in the selected benchmark run manifest.
- `timestamp` must fall inside that window's tradable range.
- `timestamp` may be an intrabar event time when the strategy uses trade-level data.
- `target_quantity` must be numeric.
- If `allow_short` is false, negative `target_quantity` values are invalid.
- Duplicate `timestamp + symbol` rows inside the same file are invalid.

Warnings may be added later for timestamps outside the session range, sparse decisions, and
non-trading timestamps. v0.1 focuses on hard format and symbol/quantity errors.

## Execution Settings

Every simulation stores the settings that will later drive evaluation:

- `initial_cash`: fixed standard value, always `10000.0` USDT.
- `fee_bps`: fee in basis points.
- `slippage_bps`: slippage in basis points.
- `allow_short`: whether negative target quantities are allowed.
- `missing_decision_policy`: v0.1 default is `hold_last`.
- `timestamp_alignment_policy`: v0.1 default is `exact_or_previous`.

Policy meanings:

- `hold_last`: missing timestamps keep the previous target quantity.
- `exact_or_previous`: a target applies from its timestamp until replaced by a later target.
- If no decision has appeared yet for a symbol, its target quantity is `0.0`.

## Workspace Layout

Uploaded simulations are stored outside source code in the MarketTestBench workspace:

```text
workspace/
  simulations/
    simulation_YYYYMMDD_HHMMSS_xxxx/
      simulation.json
      validation.json
      decisions/
        uploaded_file.csv
      results/
```

Source control should not include simulations, raw data, normalized data, or generated results.
